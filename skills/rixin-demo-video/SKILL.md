# 锐新科技 · 运行演示视频

这是 `rixin-explainer-video` 的升级版:**同一套流程、机器人、配音、混音和 E 盘渲染规则,先读那个 skill**。本 skill 只讲"怎么把运行动画穿插进去"以及怎么新增演示。范例成片:PWM(`fcc-video/PWM科普_锐新科技_方格纸_男声.mp4` 和 `_16x9.mp4`)。

## 为什么要做演示场景
纯信息卡偏静态。观众能直接看到现象(灯变暗、波形在跑、计数器在数)才会留下来;抖音单片机爆款里"原理可视化"收藏最高。演示必须和旁白数字一致,否则是误导。

## 结构原则
- 8 段里把 **1–2 段**换成演示(PWM 例子:`demoA` 三个词、`demoB` 改一个数),其余仍是信息卡;总长 ≤ 70 秒。
- 演示放在"概念刚讲出口、需要眼见为实"的位置;开场钩子和结尾预告保持信息卡。
- 一个演示场景 3–4 句旁白,每句对应一个画面变化(高亮某个词、数值切换)。

## 已有组件(`Demo.tsx`,参考副本 `Demo.tsx.ref`)
`PwmDemo` = 三个可组合的卡片:
- `led`:STM32 板 + PA6 → 电阻 → LED,信号点沿线走,LED 亮度/光晕随占空比。
- `scope`:深色示波器,方波向左滚动,橙色虚线=平均电压,"一个周期"括号;`hl` 高亮 0 周期 / 1 占空比(高电平涂绿) / 2 平均电压。
- `counter`:定时器计数条 0→999 + 比较值竖线 + 输出高/低。
- `terms`:底部三个词的芯片,随旁白句子依次高亮。
布局:从 y=330 自上而下堆叠,counter 卡片 x=250 起给左下角机器人让位;底部固定一行"动画为原理示意,非真实测量"。

场景参数(写在脚本 JSON 的 `scenes.demoA` / `demoB`):`parts` `terms` `duty:[{beat,duty}]`(到第 N 句占空比渐变过去,24 帧)。场景 id 必须在 `Video5.tsx` 的 `RENDER` 里注册(现有 `demoA` `demoB`;再加就写 `demoC: DemoScene`)。

## 数据一致性规则(最重要)
- 所有数字由同一个变量算出:占空比 d → 比较值 = round(d×1000)(计数 0..999)→ 平均电压 = 3.3×d → LED 亮度 = d。**不要在画面里手写互相独立的数字。**
- 旁白数字要和演示一致:例 PWM:50%→比较值 500→1.65V;20%→200→0.66V;90%→900→2.97V。
- 频率/周期:演示里一个周期 40 帧只是示意,旁白不要说"每秒 N 次"对应演示速度;讲频率用信息卡。
- 新演示必须在画面写"原理示意";真实参数(阈值、引脚、型号)只能来自用户提供或官方资料。

## 新增一种演示(ADC / 串口 / 中断 …)
1. 在 `Demo.tsx` 里照 `PwmDemo` 再写一个组件,输入是 `f`(场景内帧号)和一个时间表(像 `duty` 关键帧),内部所有显示量由时间表算出。
2. 每个组件拆成可组合的卡片(板子、波形/曲线、读数),用 `parts` 选;卡片统一宽 960,圆角 28,描边 5,深色屏用 `#15222B`。
3. 点子库(建议):
   - **ADC**:电位器旋钮转动 → 电压曲线 → 数字量 0–4095 读数 → 条形图;
   - **串口**:TX/RX 线上 0/1 比特依次移动,一帧 = 起始位+8 位数据+停止位,字符 'A'=0x41 逐位点亮;
   - **中断**:主循环小人一直在"查按钮",按下瞬间打断去执行 → 返回,时间轴上画出打断;
   - **消抖**:按钮触点弹跳波形 → 滤波后的干净波形。
4. 最小字号 ≥ 26(横版缩到 70%),深色底上的小字加 `stroke + paintOrder="stroke"` 描边。
5. 先用 `<Composition id="XXX-DEMO">` 做一个 8 秒的独立样片给用户看,认可后再接进完整视频。

## 检查清单(交付前)
- [ ] 抽帧:每个演示场景至少 3 帧(每句旁白一帧),看数字是否一致、文字是否重叠、机器人是否压到内容。
- [ ] 横版:同一场景再抽 1–2 帧,确认字仍清楚。
- [ ] 总时长 ≤ 70 秒;峰值 < -1 dB,响度约 -16 LUFS。
- [ ] 旁白里的英文缩写读音(PWM、ADC 等)请用户听;ASR 模型缓存若缺,下载很慢,直接让用户听。
- [ ] 渲染/输出走 E 盘(见基础 skill),成品复制到桌面,提醒微信用"文件"发送。

## 已知局限
- 目前只有 PWM 一种演示组件;其他主题的演示要新写。
- 横版右侧白板偏窄,演示在横版里约 70% 大小。
- 机器人素材清晰度受设定图限制(见基础 skill)。

## 已有的演示类型(`sc.kind`,2026-10-25 批量 4 条后更新)
`DemoScene` 现在按 `sc.kind` 分发(默认 `pwm`),组件在 `Demo.tsx`(PWM)和 `Demo2.tsx`(其余,参考副本 `Demo2.tsx.ref`):
| kind | 内容 | 关键参数 |
|---|---|---|
| `pwm` | 板子+LED、示波器、定时器计数 | `parts` `terms` `duty` |
| `foc` | 电机剖面(定子 ABC 线圈、转子、磁场箭头)+ 三相电流示波器;转子是"阻尼弹簧追磁场"的真实仿真,方波驱动会抖,正弦平滑;`dq` 模式显示 d=0、q 调力矩 | `phases:[{beat,mode:square/sine/dq}]` `iq:[{beat,v}]` |
| `dma` | 串口 DR → CPU/DMA → 内存数组 buf;`cpu` 模式 CPU 忙时丢字(显示 `?`、丢字数、被打断次数),`dma` 模式自动搬完一次通知 | `mode:cpu/dma` `period` `start` `busy:[[a,b]]` |
| `port` | 51 的 P2 口 8 个 LED + 二进制位 + 十六进制值;`chase` 模式左移成流水灯 | `phases:[{beat,mode:fixed/chase,value}]` |
| `adc` | 光敏电阻分压 → 电压 → ADC 读数(3.3V、10kΩ、12 位),数字严格按分压公式算 | `light:[{beat,v}]` |
| `echo` | HC-SR04 声波往返、Trig/Echo 波形、距离=时间×0.034÷2 | `dist:[{beat,v}]` (cm) |
场景 id 目前注册了 `demoA` `demoB` `demoC`;同一个 id 在一条视频里只能用一次。

## 批量做多条的做法(一次 4 条的经验)
- 脚本用 Python 生成:`tools/rx_scripts.py`(`write(id, prefix, rows, scenes, title, src)`,rows = `(场景, 字幕, 配音读法或 None)`;副本 `rx_scripts.py.ref`)。
- 配音稿里英文缩写写成**单字母加空格**(`D M A`、`C P U`、`S P I`),"51"写成"五一","P2"写成"P 二";字幕仍用正常写法。
- 批量渲染写成脚本文件(`E:\work\render_all.sh`),**不要**在 Bash 里用 `"E:\a\${var}"` 拼路径(会被吃掉变量);路径统一用正斜杠 `E:/...`。后台跑,逐条渲染,完成后检查时间戳和 ffprobe。
- 8 条(4 主题×竖横)约 40 分钟;脚本长度一般 75–85 秒,比"一分钟"长,发布前可问用户要不要压缩。
